## 数据清洗说明

清洗流水线分为**四阶段三表合并**：

### 1. 类型统一与异常过滤
- **样本筛选**：保留 A 股上市公司，2000 年至最新可得年份
- **主键统一**：股票代码统一为 6 位字符串（`code`），会计年度统一为整数型（`year`）
- **数值强制转换**：财务字段从 `object` 转为 `float`，非数值记录标记为 `NaN`
- **资产过滤**：剔除总资产 ≤ 0 的公司—年观测，防止后续比率计算除零

### 2. 重复值与主键处理
- **重复值规则**：按 `code`—`year` 检测重复行，保留最后一条记录
- **列名规范**：CSMAR 代码列名（如 `FS_Combas-A001000000`）映射为可读名称（如 `total_assets`）

### 3. 变量构造
- **13 个财务指标**：从负债结构（Lev, SL, LL, SDR, Cash）、盈利能力（ROA, ROE）、银行借款（SLoan, LLoan）、股权集中度（Top1, HHI5）、公司特征（Size, Age）5 个维度构造
- **年龄计算**：`Age = 会计年度 - 上市年份 + 1`

### 4. 离群值处理
- **缩尾（Winsorize）**：对 Lev, SL, LL, SDR, Cash, ROA, ROE, SLoan, LLoan, HHI5 按年度分组，分别在 1%/99% 分位数处截断
- **保留原始值**：缩尾后变量以原名存储（如 `Lev`），原始值保留为 `Lev_raw` 后缀

### 5. 多表合并
- 以 `code`—`year` 为主键，**左连接**资产负债表 → 利润表 → 股权结构表 → 上市信息表
- 最终面板：71,787 条公司—年观测，覆盖 2000–2023 年

## 数据存储与管理

### 3.1 基础要求：CSV

所有清洗后的核心数据保存为以下 CSV 文件：

- **`data/clean/firm_year_clean.csv`**：完整数据（原始变量 + 缩尾后变量，28 列，71,787 条观测）
- **`data/combined/csmar_firm_year_panel.csv`**：分析面板（缩尾后变量，16 列，71,787 条观测）

#### CSV 格式的优点

1. **通用性强**：几乎所有的数据分析工具（Python、Stata、R、Excel 等）均可直接打开 CSV，无需额外驱动程序。
2. **纯文本可读**：用记事本即可查看内容，便于手动检查数据和调试。
3. **版本控制友好**：Git 能对 CSV 进行差异对比（diff），方便审查数据变更。
4. **存储效率**：无文件大小上限，适合百万行级别的财务表格。
5. **跨平台**：Windows / macOS / Linux 之间无缝迁移，无编码兼容性问题。

#### CSV 在大规模财务数据库管理中的不足

1. **无模式约束**：不能定义字段类型、主键、外键或唯一性约束，脏数据容易混入。
2. **缺少索引**：查询时必须全表扫描，多表关联查询效率极低。
3. **不支持事务**：写入过程中断会导致文件损坏，无法回滚。
4. **无权限控制**：无法按用户或角色精细控制字段访问权限。
5. **存储冗余**：重复数据无法规范化（Normalization），相同信息在多个 CSV 中重复存储。
6. **数据完整性脆弱**：没有触发器（Trigger）或级联操作（Cascade）来维护引用完整性。

#### 为什么本次作业仍然以 CSV 作为基础提交格式

本次作业的核心目标是**展示数据清洗和变量构造的流程**，而非构建生产级数据库系统。CSV 格式满足以下需求：

- 教师/助教可以直接用 Excel 打开查看和验证清洗结果
- 课堂演示中无需配置数据库环境
- 文件体积适中（约 10 MB），便于通过 GitHub 提交和评审
- 后续分析（描述统计、回归分析等）通常直接读取 CSV，无需数据库中间层

在真实的量化研究或金融数据平台中，建议迁移至 SQLite 或 PostgreSQL 等关系型数据库，以获得更好的查询性能和数据完整性保障。

### 3.2 进阶要求：SQLite

为弥补 CSV 的不足，同时将分析面板数据存储为 SQLite 数据库，便于复杂查询演示和数据库管理教学。

#### 选择 SQLite 的理由

- **零配置**：Python 内置 `sqlite3` 模块，无需安装任何额外依赖
- **关系型查询**：支持 `JOIN`、`GROUP BY`、子查询等标准 SQL 操作
- **模式约束**：可定义主键、字段类型，防止脏数据混入
- **单文件存储**：所有数据集中在一个 `.db` 文件（约 17 MB），易于分发
- **与作业规模匹配**：71,787 行 × 3 张表的数据量，SQLite 查询性能绰绰有余

#### 数据库架构

数据库 `data/combined/csmar_finance.db` 包含 3 张表：

| 表名 | 主键 | 主要字段 | 行数 |
|------|------|----------|------|
| `firm_info` | `code` | name, industry_code, industry_name, list_date | ~5,800 |
| `firm_year_finance` | `(code, year)` | Lev, Cash, ROA, ROE, Size, Age | 71,787 |
| `ownership` | `(code, year)` | Top1, HHI5 | 71,787 |

三张表通过 `code`（股票代码）关联：`firm_info.code = firm_year_finance.code = ownership.code`。

#### 重建数据库

```bash
jupyter nbconvert --to notebook --execute 03_storage_sqlite.ipynb
```

或直接在 VS Code 中打开 `03_storage_sqlite.ipynb` → 点击"Run All"。

## 分析说明

### 1. 描述性统计与时间趋势（report.ipynb §3）

从 5 个维度分析 13 个指标：

- **负债结构**（Lev, SL, LL, SDR, Cash）：总负债率长期下行（2005 年中位数 37.7% → 2023 年 33.8%），现金比率自 2020 年后显著上升，呈"现金为王"特征
- **盈利能力**（ROA, ROE）：总资产收益率均值约 3%–4%，净资产收益率均值约 6%–8%，2020 年疫情冲击后短暂回升
- **银行借款**（SLoan, LLoan）：短期借款率高于长期借款率，企业融资以短期为主
- **股权集中度**（Top1, HHI5）：第一大股东持股比例均值约 33%–36%，前五大股东持股集中度均值约 0.14–0.16，呈分散化趋势
- **公司特征**（Size, Age）：公司规模持续增长，上市年限自然增加

### 2. 行业负债率分析（04_industry_analysis.ipynb）

- **覆盖 7 大行业**：制造业（C）、电力热力燃气（D）、建筑业（E）、批发零售（F）、交通运输（G）、金融业（J）、房地产业（K）
- **两种加权方式**：算术平均 vs 加权平均，揭示大小企业杠杆差异
- **关键发现**：房地产业（K）负债率最高（55%–65%），交通运输业（G）在 2008 年金融危机后显著去杠杆

### 3. 股权集中度分析（05_equity_analysis.ipynb）

- Top1 和 HHI5 的时间趋势
- 按行业分组的股权结构对比
- 股权分置改革（2005–2007）对股权分散化的影响

### 4. 箱线图分析（report.ipynb §4）

Lev（总负债率）在 6 个代表年份的箱线图，回答 4 个问题：

| # | 问题 | 分析结论 |
|---|------|----------|
| 1 | 不同年份 Lev 分布是否存在显著差异？ | 中位数从 2005 年 37.7% 降至 2023 年 33.8%，分布整体下移 |
| 2 | 2005–2007 股权分置改革是否影响了 Lev？ | 中位数下降 3.9 个百分点（37.7% → 33.8%），为全样本最大降幅 |
| 3 | 是否有股权分散化的证据？ | IQR 从 2005 年 26.3% 收窄至 2023 年 20.6%，企业间杠杆差异缩小 |
| 4 | 箱线图分析有哪些局限？ | 仅刻画 Lev 单变量，未控制行业/规模异质性；极端值仅反映统计异常而非财务风险 |

### 5. 综合报告（report.ipynb / report.html）

所有分析结果汇总为 `report.html`，包含交互式图表、关键数据表格和结构化分析段落。

## 如何运行

1. 安装依赖：`pip install -r requirements.txt`
2. 将 CSMAR 原始压缩包放入 `data/data_raw_zip/`
3. 运行 `01_extract_raw_data.ipynb` — 解压并识别原始数据
4. 运行 `02_clean_construct_variables.ipynb` — 清洗数据、构造 13 个变量、Winsorize 缩尾处理、导出 CSV
5. 运行 `03_storage_sqlite.ipynb` — 将面板数据存入 SQLite 数据库（进阶要求）
6. 运行 `04_industry_analysis.ipynb` — 行业负债率分析（7 大行业，两种加权方式）
7. 运行 `05_equity_analysis.ipynb` — 股权集中度分析（Top1, HHI5 时间趋势）
8. 运行 `report.ipynb` — 生成综合数据分析报告，输出结果为 `report.html`
